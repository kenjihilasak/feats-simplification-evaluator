# FEATS derived outputs v0.2.0-rc1

This private prerelease adds the complete derived outputs of Phase 3a and
Phase 3b. Both phases consume the same 854,486 canonical pairs published by
Phase 2b in [`v0.1.0-rc2`](https://github.com/kenjihilasak/feats-simplification-evaluator/releases/tag/v0.1.0-rc2).

## Phase 3a: full strategy detection

`feats-phase3a-strategy-detection-v0.2.0-rc1.zip` contains the validated full
prediction sidecars for all 12 languages and all three pinned classifiers:

- `xlmr_large_focal`: 854,486 predictions;
- `multilingual_e5_large_bce`: 854,486 predictions;
- `qwen2p5_7b_pairwise_qlora`: 854,486 predictions;
- total: 2,563,458 prediction records across 36 JSONL files.

The package includes the experiment configuration, input manifest, per-model
run configurations and JSON reports. It contains consolidated predictions, not
temporary Qwen shards. `PHASE3A_MANIFEST.csv` records the count, size and
SHA-256 of every prediction file.

- ZIP bytes: `246093476`
- ZIP SHA-256: `602599113600158601969fefd0181b22d56d67cd52f048a68445610d057623bc`

## Phase 3b: full word alignment v2

`feats-phase3b-word-alignment-v0.2.0-rc1.zip` contains the validated SimAlign
v2 sidecars for all 12 languages:

- 854,486/854,486 canonical pairs observed;
- 854,484 pairs aligned;
- two English pairs explicitly marked `skipped_model_length`;
- 15,100,065 word-alignment links;
- zero validation errors.

The v2 tokenizer routing uses surface-preserving CAMeL ATB segmentation for
Arabic, Sudachi A for Japanese, Stanza UDTB for Urdu, Stanza SSJ for Slovenian,
and language-specific spaCy tokenizers for the other languages. Every language
directory includes its input manifest, run configuration, summary and
validation report. `PHASE3B_MANIFEST.csv` records counts, tokenizer IDs, sizes
and SHA-256 hashes.

- ZIP bytes: `458669861`
- ZIP SHA-256: `b6386bb741490309f0d17f181a9d45446792d5fb62683c8bb8f6a16029a45f10`

## Pipeline nomenclature

The repository folders now follow the dependency graph explicitly:

```text
Phase 1 normalization
└── Phase 2a cleaning
    └── Phase 2b consolidation
        ├── Phase 3a strategy detection
        └── Phase 3b word alignment
```

Captured historical run configurations retain their original paths as
execution provenance. Stable `feats-phase3-*` v1 schema identifiers are also
unchanged for compatibility.
